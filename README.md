# 四人麻雀 — Vue 3 + PlayCanvas

CPU 3人と遊ぶブラウザー用の日本式四人麻雀です。ルール・点数計算にはMITライセンスの `@kobalab/majiang-core` 1.4.1、CPUには `@kobalab/majiang-ai` 1.3.0を使用します。画面・入力・Vueとの接続は新規実装し、以前のゲーム本体は現在のソースから取り除いています。

PlayCanvas Engine 2.24.0をnpmからスタンドアロンで使用します。クラウドエディターやPlayCanvasのホスティングは不要です。実行にはWebGL 2対応ブラウザーが必要です。

## 起動

Node.js 20.19以上の20系、または22.12以上を使用してください。検証環境・GitHub Actionsは24系です。

```bash
npm ci
npm start
```

表示される `http://127.0.0.1:4173` をブラウザーで開きます。通常のプレイにPlaywrightは不要です。

## 操作と設定

- 「対局開始」で対局。局名・和了・流局の表示は画面を押して続行します。
- 手牌をクリック／タップして打牌。キーボードでは卓にフォーカスし、左右キーで選択、EnterまたはSpaceで打牌します。タッチでは最初に触れた牌を選択し、指の小さなずれを許容します。指を大きく動かすと打牌を取り消します。
- チー・ポン・カン・ロン・ツモ・立直の合法な選択肢を、卓内の手牌の上に表示します。鳴きの組み合わせは小さな牌画像で確認できます。立直を選んだ後は立直可能な打牌を選びます。
- 卓内左下の「☰」メニューの「おまかせ」で、自分の手もCPUに任せられます。「タイトルへ」は現在の対局を終了します。
- 効果音・打牌速度・全画面表示は、卓内のメニューから変更できます。ルール・音・速度はブラウザーに保存します。対局途中の状態は保存しません。

メニューの「対局ルール」で、東風／東南、開始点、赤牌、喰いタン、同時和了、連荘、流し満貫、切り上げ満貫、延長戦を対局前に変更できます。対局中の変更はできません。

初期設定は東南戦・25,000点・赤なし・喰いタンあり・頭ハネ・テンパイ連荘・切り上げ満貫あり・流し満貫なし・延長なしです。途中流局、一発、裏ドラ、カンドラ、オーラス止めあり、喰い替えあり、パオなし。30,000点返し、ウマ20–10です。細かな判定は新しいエンジンのルールに従うため、以前の実装とすべて同じ対局結果になるものではありません。四家立直などの途中流局・順位点の扱いも変更しています。

上部のタイトルや卓外の操作欄を置かず、対局の操作はグリーン背景内にまとめています。メニューを開くと卓の入力を停止し、閉じると復帰します。小さい画面のメニューは内部をスクロールできます。鳴きの選択肢が多い場合は操作バー内で折り返します。素材・ライセンスは「遊び方」から英語の本文を卓内ダイアログで読めます。ページ移動や別タブの起動は行わず、閉じると元のメニューへ戻ります。

## タイトル画面

承認済みの和モダンな麻雀サロンのデザインを実装しています。3人の美少女雀士を背景に、四人麻雀のロゴ・「対局開始」「雀士紹介」「設定」を表示します。素材・ライセンスもタイトルから卓内ダイアログで確認できます。設定した対局形式と開始点を表示し、対局から戻ると同じタイトル画面を復元します。

背景は`public/js/title-salon.webp`です。人物・背景だけの元画像を`assets/title/salon-base-no-tiles.png`、3D牌の配置を`assets/title/title-tiles-layout.json`に保存しています。牌はAI画像に描き込まず、ゲーム本体と同じCC0モデルを21×28×16.5mmに揃えてPlayCanvasで描画します。手持ちの牌は指幅を基準に校正し、卓上の牌も同じ寸法と透視カメラで配置します。文字と操作ボタンはVueで描画します。

タイトル画像の再生成は次の手順です。PlaywrightのChromiumと、PythonのPillowが必要です。通常の起動・ビルドでは生成済みの画像を使います。

```bash
node scripts/render-title-tiles.mjs
python3 scripts/compose-title-art.py
python3 scripts/prepare-salon-title.py
```

3D描画・影・指先の前後関係を合成した画像は`assets/title/salon-composite.png`です。牌の寸法や配置はJSONから調整できます。合成画像に含まれる牌の図柄には麻雀豆腐の利用条件が適用され、画像全体をMITに変更するものではありません。

## 横画面の卓レイアウト

スマートフォンの横画面を基準に、横長の卓へ変更しています。正方形の3D卓を共通の透視カメラで斜め上から表示し、捨て牌・副露・ドラ表示も同じ空間で描画します。自分の手牌を手前に大きく置き、相手の手牌は奥ほど小さく表示します。左右の手牌は卓の辺に沿う一直線に揃えています。

キャラクターのアバターは3人とも同じサイズ（横画面では画面幅の13.5%、最大184px）で配置します。対面は中央上部、左右は卓の外側の中段に置き、名字を表示しません。対面のアバターと対面の手牌は一部重なる配置です。方角・4人の持ち点・局名・本場・供託・残り枚数は全自動卓風の中央表示部に集約しています。アバターには画像と名前を表示します。打牌・鳴き・メニュー・スコア表示は引き続き卓内で操作できます。縦横の画面回転では同じ対局を維持し、描画サイズと入力座標を合わせ直します。縦画面は補助表示として使用できますが、横画面を推奨します。

卓と牌の3D寸法・席配置は`src/game/model-layout.js`、描画処理は`src/game/renderer.js`にあります。牌はCC0のjust-mahjongモデルから変換したメッシュで、卓と共通の透視カメラ・照明・影を使用します。牌の底面は卓面に接し、画像を斜めに伸ばす方式は使用しません。牌面画像・ルール・CPU思考・効果音は既存のものを維持しています。

卓の背後には、自作の和モダンなサロン背景`public/js/salon-room.webp`を表示します。3D描画を透過して背景を見せ、卓と牌は同じ3D空間のまま描画します。捨て牌・副露・ドラ表示には、反射を抑えた材質と、不透明な象牙色の下地に図柄を合成した専用の牌面を使います。寝かせた牌の図柄が照明で白っぽくならないよう、図柄部分は照明から独立した描画にしています。

## 対局終了後のスコア

東風戦・半荘が終了すると、卓内に最終結果を表示します。「最終結果」「一局の履歴」「集計表」で、順位・持ち点・精算後のpt、各局の増減、対局別のスコアと雀士別の通算を切り替えて確認できます。局別の履歴は全局分を縦に並べ、一覧内をスクロールできます。全局数と最終局を表示し、「先頭へ」「最後へ」で移動できます。スマートフォンの横画面では行をコンパクトに表示します。局別の増減には立直の供託を含みます。返し点・順位点は採用エンジンの計算結果を使用します。

終了画面は「タイトルへ」か「もう一度対局」を選ぶまで表示されます。タイトルへ戻った後や次の対局中も、メニューの「設定」から「スコア・履歴」で再表示できます。集計はこのページを開いている間に終了した対局が対象で、再読み込みするとリセットされます。途中で終了した対局は集計しません。対戦相手が変わるため、通算は席ではなくキャラクターごとに集計します。

## 対戦キャラクター

対局ごとに9名から3名を重複なしで選びます。同じ対局の局替わりではメンバーを維持します。アバターと名字のない名前を卓のグリーン背景上に表示し、和了・点数精算・最終結果にも同じ名前を使います。難易度は画面に表示しません。メニューの「雀士」では9名全員を確認できます。

| 雀士 | 打ち筋 |
| --- | --- |
| ひなた | 門前主体で、素直に立直を目指す。 |
| こはる | 鳴きにも積極的。軽い手をつなぐ。 |
| すずめ | 手が遠いときは、立直に対して現物を選ぶ。 |
| れん | 有効牌の受け入れと鳴きの速度を優先する。 |
| さき | 門前を維持し、ドラを大切にする。 |
| しずく | 一向聴でも無理をせず、早めに守備へ回る。 |
| レイ | 採用AIの期待値と危険度を基に攻守を切り替える。 |
| りん | 近い期待値の候補では広い待ち・受け入れを好む。 |
| あやめ | 安い鳴きを控え、ドラと打点を育てる。 |

内部の3段階の思考方式を保ちつつ、9名に異なる判断の傾向を設定しています。強さの段階・数値・星は画面に表示しません。同じ手牌でも鳴き、守備への切り替え、速度とドラの評価が変わります。判断には自分の手牌と公開情報のみを使い、役のある手を評価するライブラリの鳴き判定とエンジンの合法手判定を使用します。個性は傾向であり、特定の手役や順位を保証するものではありません。自分の「おまかせ」は採用済みAIを使います。

アバター9種は、タイトル画面案と同じ和モダンの絵柄で、本プロジェクト用に新規生成した成人女性のキャラクターです。内蔵image_genを使い、生成元・参照した自作タイトル画像・全プロンプトを`assets/characters/`に保存しています。配布用256px PNGは`public/characters/`にあります。`scripts/prepare-character-assets.py`で書き出しとハッシュ更新を再実行できます。

## ビルド・GitHub Pages

```bash
npm run build
npm run preview
```

生成物は `dist/` です。相対パスを使用するため、`/mahjong/` などのサブディレクトリーにも配置できます。補助サーバー `node server.mjs` でも配信できます。

`.github/workflows/pages.yml` に、依存インストール・単体テスト・ビルド・Pages配信のワークフローを用意しています。GitHubリポジトリーの **Settings → Pages → Source を GitHub Actions** に設定し、`main`へpushすると実行されます。別のブランチを使う場合はワークフローの`branches`を変更してください。公開先リポジトリーの作成やpushは別途必要です。

公式手順: [Viteの静的配信](https://vite.dev/guide/static-deploy.html#github-pages)、[GitHub Pagesのカスタムワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 構成

- `src/components/MahjongGame.vue`: Vueの操作・設定画面とPlayCanvasの生成・破棄。
- `src/game/session.js`: MITエンジン、CPU、人間の選択、対局のライフサイクル。
- `src/game/renderer.js`: PlayCanvasの3D卓・牌・カメラ・照明・レイによる選択判定。
- `src/game/rules.js` / `tiles.js`: ルール設定と牌表現の変換。
- `src/game/audio.js` / `preferences.js`: Web Audioによる効果音と設定保存。
- `public/models/mahjong-tile.json`: CC0モデルから変換した牌メッシュ。
- `scripts/convert-tile-model.py`: 固定したFBXから寸法・法線・白／背面の材質境界を再現する変換処理。
- `public/js/`: 配布する画像・効果音。`assets/`と`scripts/`は制作元と生成処理。
